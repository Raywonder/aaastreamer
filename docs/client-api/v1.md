# AAAStreamer Client API v1

The `/api/client/v1` route group is the stable JSON surface for official native
Windows and macOS clients. Native clients should use these routes instead of
scraping dashboard HTML.

## Read-Only Starter Routes

### `GET /api/client/v1/health`

Public service compatibility check.

Returns:

- `success`
- `service`: version, public URL, HLS base, RTMP URL, and feature flags
- `capabilities`: unauthenticated native-client API capabilities

### `GET /api/client/v1/bootstrap`

Public bootstrap route. If the request has a valid session cookie, the response
also includes the signed-in user and role capabilities.

Returns:

- `success`
- `service`
- `branding`
- `user`
- `capabilities`

### `GET /api/client/v1/session/me`

Returns the current session user, or `null` when not signed in. This route does
not create a login session. The native-client user payload does not include
password hashes, recovery-code hashes, TOTP secrets, passkey records, or stream
keys.

### `POST /api/client/v1/auth/start`

Starts native device authorization. The client sends basic metadata such as
client name, platform, and version. The response includes:

- `userCode`
- `pollToken`
- `expiresAt`
- `authorizeUrl`

The user opens the authorization URL in the browser, signs in if needed, and
approves the displayed code.

### `GET /api/client/v1/auth/poll/:pollToken`

Polls the pending native authorization. Pending responses include `status` and
`expiresAt`. An approved response includes one `accessToken`, device metadata,
service metadata, downloads, and capabilities. The access token is returned once
and must be stored by the native client in platform secure storage.

### `GET /api/client/v1/device/me`

Bearer-token route for the authorized native client. Returns the safe user,
device metadata, permissions, and capabilities.

### `POST /api/client/v1/device/check-in`

Bearer-token route for updating the device's last-seen time, version, and
supported input/output metadata.

### `GET /api/client/v1/events`

Authenticated server-sent event stream for native clients. Accepts either a
browser session cookie or an authorized native-client bearer token.

The first event is:

```json
{"type":"connected","user":{},"capabilities":{}}
```

### `GET /api/client/v1/streams`

Authenticated stream list. Accepts either a browser session cookie or an
authorized native-client bearer token. Admins see all streams. Stream owners see
their own streams. Other signed-in users see only public/listable streams.

### `GET /api/client/v1/streams/:streamId`

Authenticated stream detail by stream id or slug, using the same authentication
and visibility rules as the stream list.

## Smoke Client

`clients/wxpython-smoke/` is the first native-client spike. It can run
health/bootstrap checks without GUI dependencies and can run a wxPython device
authorization and stream-list workflow when wxPython is installed.

OBS integration is intentionally not required by this contract. Future native
clients may add local OBS WebSocket support for scene/status helpers, while the
server continues to accept standard RTMP input from any encoder.

## Next Routes

The next client API pass should add session login/logout, stream profile edits,
stream-key rotation, encoder-key management, source controls, schedule controls,
destination controls, and moderation routes.
